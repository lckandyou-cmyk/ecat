# 可注册固件目标设计

## 目标与边界

`ecat_target_registry_t` 是数据和固件目标的唯一权威配置；目标 ID 使用非零 `uint16_t`，允许稀疏编号，数量受注册表编译期容量和设备内存限制。注册表中的固件目标拥有自己的容量、同步或异步驱动、写入单位和驱动上下文。核心保存项目、硬件、验签和防回滚等全局策略，不再维护另一份按 ID 减一索引的目标表。目标及其驱动上下文在管理器绑定期间必须保持有效；配置与访问必须串行。

固件导入仍须在任何擦写之前验证本地 ACL、目标类型、包内目标 ID、项目和硬件匹配、容量、版本和签名策略。文件提供的 ID 只能选择本地已注册且已启用的固件目标，绝不能指定物理地址或覆盖本地配置。导出使用该目标注册的只读驱动，不绕过权限控制。

## 标识与协议

EFW v2 的目标字段已有 16 位空间：允许 1～65535，0 保留为非法。已有 1～4 号包保持二进制格式和原有名称可识别；其他 ID 使用无歧义的 `T` 加四位大写十六进制，例如 `PROJECT_T002A_V1.2.3.4.efw`。打包、检查、FoE 文件名解析和 SOES 映射遵循相同规则；名称中的 ID、会话请求 ID 和签名保护的 EFW 头部 ID 必须一致。SII 既有补齐规则仅适用于 ID 3，其他目标使用常规规则。

目标查找使用注册表中的显式 ID，不得把 ID 当作数组索引或位移量。未完成状态按注册槽位保存，并在注册表绑定期内保持槽位与 ID 对应；不得对任意 ID 执行位移。SOES 的目标映射也使用有限数量的显式 ID/文件索引条目，检查重复、容量与文件表边界。

## 生命周期与兼容性

同步和异步核心共用同一目标解析、权限及 EFW 校验规则；异步挂起、取消、失败必须停止硬件并释放唯一会话。每个目标的防回滚持久化回调仍按实际目标 ID 调用。目标容量以注册的本地容量为准，不依赖固件包声明；运行期不得静默覆盖另一份核心配置。

这是 C 配置接口的有意迁移：旧四项核心配置须改为注册目标，结构体布局变化必须更新 ABI 标识并要求全量重编译。旧 1～4 号文件及 FoE 名称保持可读；不保留并行旧管理器或第二套目标配置。对容量、目标数和异步存储不引入动态分配。

## 分步交付与验证

1. 固化本设计，盘点固定编号、位掩码和协议假设。
2. 改造注册表与固件元数据校验，以显式 ID 解析单个本地目标；覆盖稀疏、大 ID、0、未知目标、重复注册、容量、权限及 ABI 错配。
3. 迁移同步和异步固件核心与会话状态，覆盖多目标隔离、签名、回滚、失败及中止，确保擦写前拒绝不匹配包。
4. 迁移 FoE/SSC/SOES 的目标名称和映射，以及 EFW 打包与检查工具；验证新旧名称、边界和工具到设备的完整链路。
5. 更新示例和中英文文档，执行普通、ASan/UBSan、哨兵、SOES、Monocypher、Bootloader 检查。每阶段保持独立提交；若阶段暂时不支持构建，必须在同一提交内补齐兼容实现或调整阶段边界。

真实 MCU、Flash 掉电行为和真实 SSC 主站仍需设备级验证；宿主测试不得冒充实机验证。
