# SOES 状态机联动测试现状与扩展规划

## 当前验证范围

`make test-soes SOES_DIR=/path/to/soes` 使用仓库外的 SOES 源码，校验固定基线后编译链接 `esc_foe.c` 和 `esc.c`，运行真实 SOES FoE 宿主测试及最小 Bootloader 集成测试。测试覆盖 FoE 写入、文件名路由、协议响应和部分失败路径；源码参与链接本身不代表其所有状态机分支已受测试。

`tests/test_core.c` 通过直接调用适配层的状态迁移后置钩子，检查升级未完成时的拦截条件与结果。这些钩子单元测试不等同于通过真实 SOES `ESC_state()` 和模拟 ESC 寄存器完成整条状态迁移链路的验证。

## 待扩展的测试

如需进一步验证真实 SOES 状态机与适配器的联动，可构建基于目标 SOES 版本的 PDI/寄存器模拟环境，并从 `ESC_state()` 驱动以下场景：

1. 升级未完成时的 BOOT → INIT 请求，检查后置钩子、邮箱停止、AL 状态及错误码的实际调用顺序和结果。
2. 错误确认后重复请求 INIT，以及完成升级后的恢复路径，检查状态和会话处理是否符合设计。
3. 按所用 ESC 数据手册模拟 AL Control、AL Status、AL Status Code 和 AL Event 等寄存器及相应事件语义；不得将 AL Event 寄存器 `0x0220` 当成 AL Status Code 寄存器。

实现前应核对所选 SOES 版本实际调用的 PDI 接口和寄存器行为，为相应路径提供模拟桩；测试也应明确区分直接调用钩子、SOES 状态机联动和物理硬件验证。

## 限制

宿主桩不能证明真实 ESC、MCU、主站的硬件时序或错误恢复行为。实际设备和 TwinCAT 的联调仍待完成；不同 SOES 版本的接口及行为也须分别核对。
