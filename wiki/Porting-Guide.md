# MCU 移植指南

本指南给出移植顺序。具体地址、擦除粒度、写入单位和启动流程必须以目标芯片手册及产品分区布局为准；仓库示例中的数值仅供说明。

## 1. 收集目标平台信息

开始修改工程前记录：

- MCU、板卡修订版、Flash 类型和容量，以及启动映像布局。
- ESC/PDI 接口、从站协议栈及版本、EtherCAT 主站和工具链版本。
- FoE 邮箱大小、可用 RAM、写入最小单位、擦除扇区大小与最长操作时间。
- 应用映像校验方式、复位/启动交接方式、看门狗和断电恢复策略。

仓库不捆绑 SOES/SSC 第三方源码。真实 SSC 接口需按项目持有的准确版本适配。

## 2. 建立设备本地配置

从 [`include/ecat_foe_conf_template.h`](../include/ecat_foe_conf_template.h) 复制并按工程配置 `ecat_foe_conf.h`。设置项目名与 ID、硬件 ID/版本、目标使能项、EFW 头缓冲区和写入单位；在目标描述符中为每个启用目标注册驱动及本地容量。

物理基址、分区上限、目标 ID 映射和允许的硬件版本只能来自设备本地配置。不得使用 FoE 文件名、WRQ 参数或 EFW 包中的数据作为物理地址或擦写长度上限。确保每次地址与长度计算都不会越过分区，也不会覆盖 Bootloader、配置区或其他目标。

## 3. 实现目标驱动

根据 [`include/ecat_foe_target.h`](../include/ecat_foe_target.h) 实现介质回调：

1. `init` 建立介质访问；若初始化失败，驱动自行清理部分资源。
2. `invalidate` 必须在任何擦除之前持久地清除旧镜像有效标记。
3. `erase_to` 按本地分区和扇区边界擦除到所需偏移。
4. `write` 只接受合法分区内、符合硬件写入对齐的写入。
5. `read` 从目标介质物理回读，供核心计算回读 CRC。
6. `finalize` 仅在完整性校验后提交有效标记；启用防回滚时改为实现符合断电恢复契约的 `finalize_with_version_floor` 联合提交。
7. `abort` 释放资源并维持无效状态，允许错误路径安全调用。

核心保证初始化成功后任何异常至多调用一次 `abort`；成功提交后不会再为该会话调用它。驱动必须对具体芯片验证擦写原子性、对齐、缓存一致性、并发访问和掉电行为。单分区覆盖可能无法保留旧映像。

## 4. 接入协议栈并串行调度

按所用协议栈实现 FoE WRQ、DATA、ERR 和升级结束路径的适配。同步回调应确保不会被中断或多个任务并发重入核心。若使用异步目标接口，提供固定缓冲区和 start/poll 驱动操作，并从协议栈主循环规律推进；不要在硬件异步操作期间提前确认尚未完成的数据包。见[协议栈接入](Stack-Integration.md)。

## 5. 真机验证门槛

在允许产品升级前，至少确认：

- 区域边界、最大有效映像、无效元数据和禁用目标都不能触及分区外内容。
- 擦除、写入、回读、提交和中止的故障注入都维持预期有效标记状态。
- 传输中断、看门狗复位和各关键写入点断电后的启动选择符合产品策略。
- 用真实从站协议栈和 EtherCAT 主站验证 FoE 分包、超时、重试、终止包、最终升级结果和状态切换。
- 验签、防回滚和升级结果报告按产品配置测试；宿主 Mock 不能证明密码学集成或掉电事务正确。

SOES 示例、配置说明与已知边界见 [`examples/bootloader_soes/README.md`](../examples/bootloader_soes/README.md)。当前仓库验证覆盖和缺项见[测试与验证](Testing.md)。
